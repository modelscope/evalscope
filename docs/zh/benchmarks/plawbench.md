# PLawBench


## 概述

PLawBench 是一个基于评分细则（rubric）的基准测试，用于评估大语言模型在真实世界中国法律实务中的表现。
它模拟了执业律师的工作流程，涵盖三个层级：在公共法律咨询中挖掘事实、通过结构化法律推理分析案件，以及起草专业法律文书。
每个测试项都配有由法律专家标注的评分细则，评分过程由 LLM 裁判依据该细则进行，而非对照单一参考答案。

## 任务描述

- **任务类型**：使用专家评分细则对开放式中文法律生成内容进行评分
- **输入**：当事人陈述，或案件描述加上一个法律问题
- **输出**：问题列表、结构化的案件分析，或完整的法律文书
- **领域**：中国法律实务（个人事务、婚姻家庭、公司治理、知识产权、刑事与民事诉讼、跨境事务、劳动纠纷、环境安全等）

## 主要特点

- 共 280 个样本，分为四个子集，分别对应 PLawBench 的四类任务：
  - `case_analysis` (250): 案件分析，从四个维度评分——结论、案件事实、推理过程和引用法条。答案必须遵循【结论】/【案件事实】/【推理过程】/【法条依据】的结构。
  - `legal_consultation` (18): 模型扮演律师角色，需提出 10-25 个可验证的后续问题，以揭示当事人遗漏或歪曲的事实。
  - `plaintiff_statement` (6): 根据当事人的陈述起草起诉状。
  - `defendant_statement` (6): 根据当事人的陈述及对方起诉状起草答辩状。
- 当事人陈述故意模糊、情绪化或具有误导性，因此模型必须识别陷阱，而不是简单复述当事人的主张。
- 任务提示和评分标准遵循官方发布版本，且 `case_analysis` 的评分细则保留了其按维度分配的分数。裁判输出指令已调整为单个 JSON 对象格式，解释内容包含在声明字段内；得分不保证与官方提示格式完全匹配。

## 评估说明

- 需要 LLM 裁判：设置 `judge.strategy='llm'`（或 `'auto'`，这将为此基准启用裁判），并提供 `judge.models`。不支持 `judge.strategy='rule'`。
- 指标为 `[0, 1]` 区间内的得分比例。每个子集均报告 `acc`；`case_analysis` 额外报告 `conclusion_acc`、`fact_acc`、`reasoning_acc` 和 `law_acc`。这些指标与官方排行榜列一一对应：`legal_consultation` 对应 Task1，`case_analysis` 对应 Task2-Avg 及其四个维度，两个文书起草子集分别对应 Task3-Plaintiff 和 Task3-Defendant。
- 请比较各子集的得分，而非 `OVERALL` 行。`OVERALL` 是逐样本的平均值，因此 `case_analysis` 对其影响占主导（280 个样本中有 250 个）。论文中的 `Overall` 列是三个任务得分的等权平均值，这与发布的表格数据吻合度更高（在官方排名的 24 个模型上进行拟合，平均绝对误差为 0.72，而按样本加权平均值的误差为 2.87）。
- 评分细则的总分来自数据集，而非裁判输出，且获得的分数会被限制在 `[0, max_points]` 范围内，因此即使裁判错误地报告了分母，也不会扭曲最终得分。
- 相对于官方脚本，`case_analysis` 的裁判输出模板已进行修复，官方脚本存在 JSON 格式错误并将结论部分固定为零分；在此处，每个部分均根据其评分细则分配进行评分。
- 裁判模型的传输重试策略通过其 `generation_config` 配置。如果回复仍不符合输出契约，则视为不可用并被排除，而不是静默地计为零分。
- 案件分析裁判会返回较长的逐项明细。请在 `judge.models[].generation_config` 中为裁判提供较大的 `max_tokens`（例如 8192）。
- 文书起草子集要求生成 2,500-3,000 字的法律文书，因此被评估的模型也需要较大的 `generation_config.max_tokens`。截断的文件会被评为不完整文档并接近零分，这会因与法律能力无关的原因拉低 Task3 的得分。

## 使用方法

### 使用 CLI

```bash
evalscope eval \
    --model YOUR_MODEL \
    --api-url OPENAI_API_COMPAT_URL \
    --api-key EMPTY_TOKEN \
    --datasets plawbench \
    --judge '{"strategy":"llm","models":[{"model_id":"YOUR_JUDGE_MODEL"}]}' \
    --limit 10  # 正式评估时请删除此行
```

### 使用 Python

```python
from evalscope import run_task
from evalscope.config import TaskConfig

task_cfg = TaskConfig(
    model='YOUR_MODEL',
    api_url='OPENAI_API_COMPAT_URL',
    api_key='EMPTY_TOKEN',
    datasets=['plawbench'],
    judge={'strategy': 'llm', 'models': [{'model_id': 'YOUR_JUDGE_MODEL'}]},
    dataset_args={
        'plawbench': {
            # subset_list: ['case_analysis', 'legal_consultation', 'plaintiff_statement']  # 可选，用于评估特定子集
        }
    },
    limit=10,  # 正式评估时请删除此行
)

run_task(task_cfg=task_cfg)
```
