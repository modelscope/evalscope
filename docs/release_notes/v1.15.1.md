## 中文版

### 基准测试数据集

- 通用推理：新增 BBEH（BIG-Bench Extra Hard）及 HLE-Diamond，后者分别报告整体、推理和知识分区准确率。
- 多语言理解：新增 Global-MMLU、Global-MMLU-Lite 和 MMLU-Indic，覆盖多语言、多文字系统与罗马化输入；Global-MMLU 系列同时报告文化敏感与文化无关问题的准确率。
- 印度语言生成：新增 IndicGenBench 的 FLORES-IN 翻译及 CrossSum-IN 跨语言摘要，以语料级 chrF 评分；本次不包含 XQuAD-IN 和 XorQA-IN。
- 图像生成：新增 CVTG-2K、LongText-Bench 文字渲染评测，Qwen-Image-Bench 创意生成评测及 DPG-Bench 密集提示词对齐评测，支持各基准文档规定的在线生成或离线图像评测方式。

### 功能增强

- 评测诊断：新增 `facts` 事实分析和显式模型驱动的 `diagnose`，连接评测结果、问题样本、Agent 步骤与原始证据；严格校验模型输出和引用，将模型提出的原因与官方结果分开展示。
- Web 协议：连接编辑器支持 OpenAI Responses 与 Anthropic Messages，完善配置保存、导入导出及评测/压测请求转发。
- 压测对比：支持按工作负载分组对比多次运行、选择任意基线、查看配置差异，以及满足固定随机输入条件时的输入长度趋势；区分并发数和请求速率坐标轴。
- 压测统计：SLA 重复运行报告均值、标准差及均值的双侧 95% 置信区间；支持记录 `--device-count` 并报告单设备吞吐。
- 报告访问：预测列表接口支持 ETag 和条件请求，减少反复浏览大型报告时的数据处理与传输。
- CLI：`benchmark-info --list --format json` 和 `--format markdown` 可导出结构化列表或 Markdown 表格，保留标签过滤和默认文本输出。
- 聚合性能：增量计算 vote@k、pass@k 和 pass^k 曲线，优化决策 AUPRC 的阈值聚合，减少重复扫描。
- 贡献流程：完善 PR 分类及按当前提交进行的 AI 辅助审查，支持内联发现、证据核查、结果历史和失败诊断。

### 文档优化

- 在 21 项基准指南中补充 E2B 沙箱支持，完善模板、依赖及运行条件说明。
- 更新新增基准、压测设备数、模型分析配置、结构化主指标和参数使用说明。
- 补充 LongBench-Write 裁判配置及仅评测长度的方法，说明官方示例裁判快照已退役。
- 改善文档翻译中的代码保留、长文档分节和错误处理，并修正贡献环境的 Python 要求。

### 问题修复

- 数据选择：修复 `limit=0` 被当作全量评测、布尔 limit 被隐式转换、先截断再过滤导致样本不足的问题；统一远程、本地及内存数据的转换、过滤、重复与编号流程，并修复分层采样的覆盖和配额舍入。
- 配置与缓存：恢复 JSON/YAML 中结构化 `primary_metric`，默认 k 类报告仍保留普通均值；支持带 UTF-8 BOM 的 JSON 配置；修复模型路径尾部斜杠导致输出标识变为 `untitled`。
- 多选与提示：无答案标记时不再从长推理中猜测最后一个选项字母；修复中文 few-shot 答案格式、自定义模板被忽略，以及 ScienceQA/A-OKVQA 打乱选项后显示内容与标签不一致的问题；few-shot 示例保留原有选项顺序。
- 评分协议：对齐 Arena 单向胜负的 Bradley-Terry 拟合、ProcessBench 子集等权 F1、IFBench 校验器、DROP 多跨度答案、VQAv2 人类答案归一化、MathVista 浮点精度及 ARC-AGI-2 最终网格选择。

- 移除未实现请求处理的原生 DashScope 压测插件，文档改为使用 OpenAI 兼容协议。

### 升级说明

- `limit=0` 或 `0.0` 现在选择零样本；需要全量评测时请省略 `--limit` 或在 Python 中使用 `limit=None`。零限制仍进行配置与标识准备，不等同于 dry-run。
- BFCL-v3/v4 的上游数据与可执行检查器已更新，评测版本为 `v1.2`；建议使用新输出目录重新评测。BFCL-v4 部分子集运行的汇总分数不再只平均已测类别，应结合实际样本数解读。
- 多项输入、提示、答案提取及评分发生变化，请核对各基准的 `evaluation_version` 和答案提取版本。输入或 few-shot 提示变化需要重新生成预测；仅评分变化可按文档重新评分。
- BFCL 和 CVTG-2K 的可选依赖包含 NumPy/PyArrow 兼容性约束；CVTG-2K 本地 OCR 请安装 `evalscope[cvtg_2k]`。核心安装不因这些 extras 全局固定旧版 NumPy。
- 原 `--api dashscope` 压测请改为 `--api openai` 和 DashScope OpenAI 兼容端点；评测模型的 DashScope 兼容访问不受该插件移除影响。
- 模型诊断需要显式配置模型，可设置调用预算；其输出属于有引用的分析建议，不替代基准分数，只有事实分析时不新增模型调用。DPG-Bench、LongText-Bench 等使用视觉模型评分时，不同裁判结果不可直接视作官方裁判下的同一分数。

## English Version

### Benchmark Datasets

- General Reasoning: Added BBEH (BIG-Bench Extra Hard) and HLE-Diamond, with separate overall, reasoning and knowledge accuracies for Diamond.
- Multilingual Understanding: Added Global-MMLU, Global-MMLU-Lite and MMLU-Indic across languages, scripts and romanized input. Global-MMLU benchmarks also report culturally sensitive and culturally agnostic accuracies.
- Indic Generation: Added IndicGenBench FLORES-IN translation and CrossSum-IN cross-lingual summarization with corpus chrF. XQuAD-IN and XorQA-IN are not included.
- Image Generation: Added CVTG-2K and LongText-Bench text rendering, Qwen-Image-Bench creative generation, and DPG-Bench dense-prompt alignment. Online generation and offline-image workflows follow each benchmark's documented support.

### Feature Enhancements

- Evaluation Diagnostics: Added `facts` analysis and explicitly configured, model-driven `diagnose`, linking results to affected samples, agent steps and source evidence. Model outputs and citations are validated, and proposed causes remain separate from official outcomes.
- Web Protocols: Added OpenAI Responses and Anthropic Messages to connection editing, with configuration persistence, import/export and evaluation/performance request forwarding.
- Performance Comparison: Compare multiple runs grouped by workload, select arbitrary baselines, inspect configuration differences and view validated fixed-random input-length trends. Concurrency and request-rate comparisons use separate axes.
- Performance Statistics: Repeated SLA probes report means, standard deviations and two-sided 95% confidence intervals for means. Record `--device-count` to report per-device throughput.
- Report Access: Prediction-list endpoints support ETag and conditional requests to reduce processing and transfers during repeated inspection of large reports.
- CLI: Export benchmark listings with `benchmark-info --list --format json` or `--format markdown`, preserving tag filtering and default text output.
- Aggregation Performance: Incrementally compute vote@k, pass@k and pass^k curves, and reduce repeated threshold scans in decision AUPRC.
- Contributions: Improved PR classification and current-commit AI-assisted reviews, including inline findings, evidence checks, review history and failure diagnostics.

### Documentation

- Added E2B guidance to 21 benchmark descriptions, including templates, dependencies and runtime conditions.
- Documented new benchmarks, serving-device counts, model diagnostics, structured primary metrics and configuration usage.
- Documented LongBench-Write judge configuration and length-only evaluation after retirement of the official example judge snapshot.
- Improved code preservation, section splitting and failure handling in translation, and corrected contributor Python requirements.

### Bug Fixes

- Data Selection: Fixed zero limits triggering full evaluation, boolean limits being coerced, and filtering after truncation producing too few samples. Unified remote/local/in-memory post-processing and corrected stratified coverage and quota rounding.
- Configuration and Caching: Restore structured `primary_metric` from JSON/YAML while retaining ordinary means in default k-metric reports; accept UTF-8 BOM JSON; preserve model IDs for paths ending in a slash.
- Multiple Choice and Prompts: Stop guessing a trailing option letter from unmarked reasoning. Fixed Chinese few-shot answers, ignored custom templates and displayed-choice/label mismatches after ScienceQA/A-OKVQA shuffling. Few-shot examples retain their authored order.
- Evaluation Protocols: Aligned one-sided Arena Bradley-Terry fits, ProcessBench subset-macro F1, IFBench verifiers, DROP multi-span answers, VQAv2 human-answer normalization, MathVista float precision and final ARC-AGI-2 grid selection.
- Scoring and Reports: Fixed OCRBench v2 bilingual primary scores and RefCOCO IoU comparisons, NER literal less-than/empty tags, and ASR insertion accounting for empty references without division by zero or silently dropping hallucinated words.
- BFCL: Upgraded to `bfcl-eval==2026.3.23`, stabilized selected memory scenario preparation, snapshot validation and execution state, aligned v4 aggregation with official full-category/zero-score rules, and warn early about missing search credentials.
- Models and Media: Pass dictionaries to local chat templates, avoid duplicate special tokens and treat temperature 0 as greedy decoding. Fixed image MIME types, path normalization, size limits and case-insensitive HTTP schemes; forward custom TTS headers/query parameters.
- Agents and Artifacts: Allow 64 MiB bridge request bodies, correct tool-call stop reasons and cross-protocol cached-token accounting, isolate concurrent SkillsBench/GDPval artifacts, and tolerate absent Terminal-Bench usage.
- Image and Code Evaluation: Restored relative-path offline GEdit evaluation, preserve failed/degraded text-rendering scores, install matplotlib in SciCode sandboxes, and retain PyPI when installing CPU torch for DS1000.
- Performance Protocols: Require terminal Responses stream events, preserve complete JSON request bodies, treat JSON scalars as plain text, count instructions/tool-result input tokens, avoid unnecessary proxy/netrc lookups and prepare warmup-overlap replacement requests ahead of dispatch.
- Resources and UI: Fixed newer NLTK resource trust under permissive umasks, WMT24++ scoring-failure records, protocol labels, chart tooltips and task-menu dismissal.
- Removed the native DashScope performance plugin, which had no request-processing implementation, and documented the OpenAI-compatible alternative.

### Upgrade Notes

- `limit=0` and `0.0` now select no samples. Omit `--limit` or use Python `limit=None` for a full evaluation. Configuration and identity preparation still occur; zero limit is not dry-run.
- BFCL-v3/v4 use updated upstream data and executable checkers at evaluation version `v1.2`; use fresh output directories for reevaluation. Partial BFCL-v4 runs no longer average only evaluated categories; interpret aggregate scores alongside actual evaluated counts.
- Check benchmark `evaluation_version` and answer-parser versions for input, prompt and scoring changes. Input/few-shot changes require new predictions; scoring-only changes can use documented regrading.
- BFCL and CVTG-2K extras carry NumPy/PyArrow compatibility constraints. Install `evalscope[cvtg_2k]` for local OCR. These extras do not globally pin the core installation to an older NumPy.
- Replace performance `--api dashscope` with `--api openai` and the DashScope OpenAI-compatible endpoint. Removing this plugin does not remove compatible-endpoint model evaluation.
- Model diagnostics require explicit model configuration, support call budgets and produce referenced proposals rather than replacement benchmark scores; facts-only analysis adds no model calls. Scores from different vision judges for DPG-Bench, LongText-Bench and similar tasks are not interchangeable with official-judge results.
